# Spec: Этап 1 «Боёвка соло, без сети» (app-88s)

**Дата:** 2026-08-02 · **Статус:** на апруве владельца (v2 — после self-review
4 субагентами по `review_spec.md`)
**Вход:** ADR-001 (§5, §9, §10), ADR-002 (§3, §4, §5, §8 Этап 1), ADR-003 §9,
handoff_app_server.md, brainstorm 2026-08-02
**Ветка:** `feature/app-88s-stage1-solo-combat` (worktree `.worktrees/app-88s-stage1-solo-combat`)

## 1. Цель

Ядро удовольствия: 5 минут соло-геймплея, в которых стрелять приятно. Движение с
моментумом, дэш с i-frames, камера ¾, прицел курсором, одно оружие с физическими
снарядами, два типа мобов на стейт-машинах, волны от seed, HP/смерть/рестарт,
полный game-feel-пасс по чеклисту ADR-001 §10. Вся игровая логика — в
`Ring.Simulation` (чистый C#, тики), баланс — в ScriptableObjects, Presentation —
отдельным слоем. Сеть, зоны арены, лут, способности — не в этом этапе.

## 3. Скоуп

### 3.1. Слои и asmdef

- **`Ring.Simulation`** (есть: `client/Assets/Scripts/Simulation/`) — вся игровая
  логика; новые подкаталоги `Movement/`, `Combat/`, `AI/` + расширение `Core/`
  (`Ring.Simulation.Core.SimulationWorld`, `StateHash64` — расширяются, не
  заменяются). `noEngineReferences: true`, только `Unity.Mathematics` — без
  изменений.
- **`Ring.Data`** (новый asmdef, `client/Assets/Scripts/Data/`) — SO-классы
  баланса + конвертация в plain `SimConfig`. Ссылка на `Ring.Simulation`.
  **Р1:** слой `Scripts/Data/` отсутствует в ADR-002 §3 — фиксируется
  **Amendment A7** (вносится этим этапом); CODEOWNERS дополняется строкой
  `/client/Assets/Scripts/Data/` (server-ownership) и чинится мёртвый путь
  `/client/Tests/` → `/client/Assets/Tests/` (правка санкционируется апрувом
  спеки, выполняется в таске финализации).
- **`Ring.Presentation`** (новый asmdef, `client/Assets/Scripts/Presentation/`) —
  раннер, интерполяция, камера, VFX/звук/game feel, input-обвязка, HUD/оверлеи.
  Ссылки: `Ring.Simulation`, `Ring.Data`, `Unity.InputSystem`, `Unity.Mathematics`.
- **`Ring.Editor`** (есть) — получает ссылку `Ring.Data` (дев-обвязка hot-tweak).
- **`Ring.Simulation.Tests`** (есть, `client/Assets/Tests/EditMode/`) — получает
  ссылку `Ring.Data` (тесты конвертации SO→SimConfig); новые тестовые файлы
  кладутся в него, отдельные asmdef не заводятся.
- Поток кадра: `Input → SimInput → N×Tick() → снапшот+события → рендер/VFX`.

### 3.2. Тик-петля и часы Presentation

- **`FixedStepAccumulator`** — чистый C#-класс (тестируется в EditMode):
  накапливает время кадра, кап 0.25 с (выброшенное время логируется), выдаёт
  число тиков кадра и alpha = `acc / TickDt`. `SimulationWorld.TickDt` —
  единственный источник dt (в SO/`SimConfig` не дублируется).
- **`SimulationRunner`** (MonoBehaviour, Presentation) — единственный владелец
  вызова `Tick`; источник времени — `Time.unscaledDeltaTime`.
  **`Time.timeScale` в проекте не используется никем** (остановил бы симуляцию —
  нарушение решения 6а и несовместимость с Э2). API мира не содержит мутирующих
  методов, кроме `Tick(in SimInput)` и применения конфига; в Э2 раннер
  заменяется тик-источником FishNet без изменений Simulation.
- **Сэмплирование ввода — раз в кадр** (Input System физически не даёт чаще):
  удерживаемые значения (`moveDir`, `aimPoint`, `fireHeld`) идентичны для всех
  тиков кадра; edge-защёлки (`dashRequested`) взводятся событиями Input System
  между кадрами (ИЛИ-объединение), **потребляются ровно первым тиком кадра** и
  гаснут. Тест: 2 тика в одном кадре → ровно один дэш.

### 3.3. Модель данных, RNG, хеш, детерминизм (Simulation)

- Состояние (все векторы `float2`; игрок — **список длиной 1**: форма контракта
  не меняется в Э2):
  - `PlayerState`: pos, vel, aimPoint, recoilOffset, hp, alive, dashTimer,
    dashCooldown, dashDir, iframeTimer, dashBufferTimer, fireCooldown;
  - `MobState`: id, type, pos, vel, hp, aiState, stateTimer, fireCooldown,
    strafeSign;
  - `ProjectileState`: id, owner, pos, prevPos, vel, damage, radius, ttl;
  - `WaveState`: waveIndex, phaseTimer, pendingSpawns (долг спавна по типам),
    aliveCount;
  - мир: tick, rng, nextEntityId, **метрики захода** (kills, wavesCleared,
    shotsFired, shotsHit, dashesUsed, damageTaken, deathTick) — метрики живут в
    Simulation и входят в хеш.
- Списки предаллоцированы (капы §3.15); удаление — swap-remove (детерминировано);
  ID — монотонный `nextEntityId`.
- **Хеш** — существующий `StateHash64` (FNV-1a 64; golden-vector тест
  сохраняется). Float — через новые перегрузки `Add(hash, float)` /
  `Add(hash, float2)` **внутри `StateHash64`** (`math.asuint`; `-0.0`
  нормализуется в `+0.0`; NaN запрещён инвариантом §3.8). Канонический порядок:
  tick → rng.state → nextEntityId → players → count(mobs)+mobs →
  count(projectiles)+projectiles → wave-state → метрики.
  **Правило: любое поле, читаемое тиком, входит в хеш**; тест «изменение каждого
  поля меняет хеш».
- **RNG один** — `SimulationWorld._rng` (`Unity.Mathematics.Random`); порядок
  потребления фиксирован обходом тика (игрок → мобы → снаряды → волны);
  **отдельные инстансы `Random` запрещены** (хеш перестал бы покрывать
  состояние). Использовать штатные `NextFloat2Direction()` / `NextFloat(min,max)`.
- **`SaveState()` / `RestoreState()`** — полная копия состояния мира (шов под
  rollback Э2; усиливает тесты: save → N тиков → restore → N тиков → равные хеши).
- **Миграция Э0**: сигнатуры → `SimulationWorld(long seed, in SimConfig)` и
  `Tick(in SimInput)`; scaffold-поле `_lastNoise` удаляется (его роль берёт
  реальное состояние). `DeterminismTests` **расширяются, не переписываются**:
  pinned-тесты (golden vector FNV, свёртка seed 0/−1, zero-seed, negative-seed)
  сохраняются с адаптацией сигнатур; смена состава хеша ожидаема (decision log).
- **Float-дисциплина**: только `Unity.Mathematics` (`Mathf`/`System.Math` в
  Simulation запрещены); `[BurstCompile]` в Simulation запрещён; трансцендентные
  функции — по минимуму (сравнение квадратов дистанций, где возможно).
  Кросс-платформенный детерминизм — вопрос Э2 (decision log); дисциплина выше
  удешевляет переход.
- Отладка расхождений: дев-утилита трассы «tick → hash» (лог по тикам).

### 3.4. Движение и симуляционная физика

- **Геометрия — один модуль** `Ring.Simulation.Core.Geometry`:
  `CircleVsCircle`, `SegmentVsCircle` (свип), `CircleInsideRing` (стена арены —
  тест «изнутри», отдельная формула), `ResolvePushSlide`. Переиспользуется
  движением, дэшем, снарядами и AI (LoS). Векторная математика — только
  `Unity.Mathematics` (`normalizesafe`, `lengthsq`, `dot`).
- Моментум: ускорение к желаемому направлению, трение при отпущенном вводе,
  кап скорости.
- Дэш: фиксированная скорость/длительность, кулдаун, окно i-frames; направление
  фиксируется на старте (`dashDir`); ввод буферизуется (`dashBufferTimer`);
  перемещение дэша — **свипом** (без туннелирования сквозь препятствия).
- **Разрешение коллизий — collide-and-slide, до 3 итераций за тик**;
  детерминированный порядок контактов (по индексу препятствия), skin-эпсилон
  после депенетрации. Тесты: угол «стена+препятствие» — скольжение без
  залипания; скольжение не увеличивает модуль скорости.
- Separation мобов: силы считаются по всем парам, применяются после подсчёта
  (двойной буфер) — без систематического перекоса первого в списке.

### 3.5. Боёвка

- Оружие одно, hold — непрерывный огонь. Кулдаун выстрела **переносит дробный
  остаток** (`cd += interval`), спавн снаряда смещается на `remainder × speed`
  (sub-tick spawn) — RPM не квантуется тикрейтом.
- **Снаряды — свип-тест**: отрезок `prevPos→pos`, расширенный на радиус, против
  стены, препятствий и целей; выигрывает наименьший t. Препятствие раньше
  цели → `ProjectileBlocked`, урона нет. Туннелирование исключено по построению.
- **Матрица поражения**: снаряд игрока поражает только мобов и умирает на первой
  цели (пробития нет); снаряд Gunner поражает только игрока, мобов игнорирует;
  контактный урон Chaser — **только в тике удара** (по завершении телеграфа при
  дистанции ≤ радиуса удара), не непрерывный, на мобов не действует. Урон в окне
  i-frames поглощается полностью.
- Отдача: `recoilOffset` в `PlayerState` (считается в Simulation — влияет на
  направление снарядов, т.е. на исход; ADR-001 §9), экспоненциальный возврат;
  **отдаётся в снапшот** — прицел и конус разброса рисуются от него (§3.7, §3.11),
  игрок видит правду.
- `canFireWhileDashing` — параметр `WeaponConfig` (вкус владельца, веха 1).
- Смерть моба → событие `MobDied` (единственный сигнал смерти; флага
  «фатальность» в `ProjectileHit` нет — Presentation коррелирует по id цели).
  Труп — Presentation, персистентен (§3.11).

### 3.6. AI и волны

- `ChaserDrone`: `Idle → Chase → Attack` (телеграф → удар → откат; тайминги в
  конфиге — база game feel уклонения). **Обход препятствий**: тангенциальный
  обход круга; выбор стороны детерминирован (знак векторного произведения, при
  нуле — по чётности id).
- `GunnerDrone`: `Idle → Reposition` (предпочтительная дистанция, страйф по
  `strafeSign`) → `Fire`. **Выстрел только при свободной линии огня**
  (`SegmentVsCircle` против препятствий). Упреждение — перехват с `leadFactor`
  0..1; вырождения: неподвижный игрок → выстрел точно в точку; решения перехвата
  нет (скорость цели ≥ скорости снаряда) → фолбэк в текущую позицию, без NaN.
- Таймеры AI — **в секундах, продвигаются на dt** (переход на 10–15 Гц в Э2 не
  потребует переписывания FSM).
- **Спавн волн — детерминирован и завершаем**: кандидат = угол на кольце из RNG
  мира; до `maxSpawnAttempts` (дефолт 16) попыток; отбраковка — пересечение с
  препятствием, живым мобом, дистанция до игрока < `minSpawnDistanceToPlayer`;
  исчерпание → детерминированный фолбэк по фиксированной сетке K углов; валидных
  нет → **долг в `pendingSpawns`** (wave-state, в хеше), отработка следующими
  тиками. Количество потреблённых значений RNG зависит только от состояния мира.
- `WaveConfig`: пауза между волнами, рост численности (с капом `maxMobsPerWave`),
  соотношение типов по индексу волны.

### 3.7. Контракт Simulation↔Presentation

- **Снапшот**: двойной предаллоцированный буфер (swap ссылок), копия за тик без
  аллокаций. **Сопоставление сущностей между снапшотами — только по стабильному
  int-ID**, не по индексу (в симуляции swap-remove): map ID→вьюха с пулом; новая
  сущность рисуется без интерполяции от позиции спавна; исчезнувшая снимается
  немедленно (визуальный след — через события). В снапшоте дополнительно:
  `recoilOffset` и текущий разброс (для честного прицела).
- **События**: один tagged-union `SimEvent` (`Kind` + `tick` + payload
  pos/id/type) в одном предаллоцированном буфере ёмкостью `maxEventsPerFrame`
  (расчёт на 8 тиков худшего случая — кап аккумулятора). Переполнение не
  аллоцирует: новые события отбрасываются с инкрементом счётчика `droppedEvents`
  (виден в дев-оверлее; тихая потеря запрещена). Дренится после пачки тиков кадра.
- Состав: `ProjectileFired`, `ProjectileHit`, `ProjectileBlocked`,
  `ProjectileExpired`, `MobSpawned`, `MobDied`, `PlayerDamaged`, `PlayerDashed`,
  `PlayerDied`, `WaveStarted`, `WaveCleared`. Поле `tick` — во всех (задел под
  дедупликацию при ресимуляции Э2; сам механизм — Э2, decision log).

### 3.8. Input

- **Переиспользуем существующий project-wide ассет
  `client/Assets/InputSystem_Actions.inputactions`** (второй ассет не создаём;
  ссылка `m_configObjects` в `EditorBuildSettings.asset` сохраняется):
  карта `Player` перестраивается в `Gameplay` — `Move` остаётся (WASD/стик);
  `Attack`→`Fire` (`<Mouse>/leftButton`); `Jump`→`Dash` (`<Keyboard>/space`);
  `Look`→`Aim` с ребиндингом на `<Mouse>/position`; неиспользуемые действия
  шаблона (Interact/Crouch/Sprint/Previous/Next) удаляются; карта `UI`
  сохраняется (оверлеи, `Submit` = рестарт). `generateWrapperCode` остаётся 0 —
  чтение через `InputActionReference`; край — штатным
  `WasPressedThisFrame()`/callbacks; Update Mode — дефолтный (Dynamic).
- Presentation: `Aim` → луч камеры в плоскость арены → `float2`; неудача
  (луч почти параллелен плоскости, потеря фокуса, нет устройства) →
  переиспользуется последний валидный `aimPoint`, NaN не передаётся. Системный
  курсор скрыт, рисуется прицел-маркер (обновление per-frame, не тик-квантованное).
- **Санитизация — обязанность Simulation** (в Э2 вход недоверенный): на входе
  тика `moveDir` = `normalizesafe` + кап длины ≤ 1; `aimPoint` — `isfinite` +
  кламп в круг радиуса 2×arenaRadius от игрока, невалидный → последний валидный.
  Инвариант: после любого тика все поля состояния `isfinite` (тест враждебного
  ввода: NaN, Inf, нулевой и сверхдлинный `moveDir`, `aimPoint` 10^9).
- `SimInput` (plain): `moveDir`, `aimPoint`, `fireHeld` (зажат в момент сэмпла
  ИЛИ нажимался с прошлого кадра), `dashRequested` (защёлка, потребляется первым
  тиком кадра — §3.2).

### 3.9. Баланс: SO → SimConfig и hot-tweak

- SO-ассеты в `client/Assets/Data` (`[CreateAssetMenu]`, `[Range]`):
  `HeroConfig`, `WeaponConfig`, `MobConfig` (один класс, два ассета: Chaser,
  Gunner), `WaveConfig`, `ArenaConfig`, `GameFeelConfig`, `CameraConfig`.
  Game-feel/камерные числа Simulation не касаются — Presentation читает их SO
  напрямую.
- Конвертация `Ring.Data` → **иммутабельный** plain `SimConfig` с валидацией:
  NaN/отрицательные значения/нулевые радиусы/диапазоны; препятствия целиком
  внутри арены; точка спавна игрока свободна; кольцо спавна перекрыто не
  полностью. Нарушение — явная ошибка при старте, не «странный матч».
- **Hot-tweak**: `OnValidate` SO → пересборка `SimConfig` → **атомарная замена
  на границе тика**. Миграция живого мира: hp клампится вниз к новому максимуму,
  таймеры — в `[0, новое значение]`, wave-state сохраняет индекс волны.
  **Топология арены (радиус, препятствия) в hot-tweak запрещена** — её смена =
  рестарт мира с пересборкой грейбокса. Мир помечается `configTweaked` — оверлей
  и лог показывают seed с пометкой «прогон с правками, не воспроизводится».
  Весь hot-tweak-путь — `#if UNITY_EDITOR || DEVELOPMENT_BUILD` (в серверный
  билд Э2 не попадает). Тесты: миграция сохраняет инварианты; одинаковые
  последовательности твиков → равные хеши.

### 3.10. Грейбокс-арена, сцена, HUD

- Истина — `ArenaConfig` (радиус, список препятствий: позиция+радиус); из него
  Simulation берёт коллизии, Presentation строит грейбокс примитивами (пол,
  кольцо стены из сегментов, препятствия-цилиндры). Расхождение сим/визуал
  исключено по построению. Валидация — §3.9.
- Стиль: тёмная среда, эмиссивные материалы снарядов/подсветок (ADR-001 §10);
  лоуполи-арт — не в этом этапе.
- Сцена `client/Assets/Scenes/Main.unity` дополняется: раннер, камера-риг,
  спавн игрока, HUD, оверлей смерти, дев-оверлей (droppedEvents, счётчики).
- **HUD** (uGUI + TMP из установленного `com.unity.ugui`; EventSystem +
  `InputSystemUIInputModule`): HP игрока, кулдаун дэша, номер волны. Полоски HP
  мобов — не в этом этапе.
- Мишени вехи 2 — `MobState` без AI (отдельная сущность не вводится).

### 3.11. Game-feel-пасс (полный чеклист ADR-001 §10)

- **Hitstop** (решение 6а): исключительно флаг Presentation — на 30–50 мс
  фиксируется текущая пара снапшотов (визуальная интерполяция замирает),
  симуляция продолжает тикать; по завершении интерполяция продолжается от
  актуальной пары (короткий визуальный догон — параметр). `Time.timeScale` не
  используется (§3.2). Длительности **не стекаются**: новое попадание
  переустанавливает таймер; суммарная доля заморозки ограничена
  `maxHitstopRatio` в секунду (hold-огонь не превращается в слайд-шоу). Звук и
  тряска во время hitstop не замораживаются. Скоуп (только цель / весь кадр) —
  параметр.
- **Вспышка шейдера цели**: `MaterialPropertyBlock` + `_EmissionColor` (URP
  Lit) — без инстансирования материалов.
- **Микротряска камеры**: trauma-модель (события добавляют trauma, амплитуда ∝
  trauma², кламп максимума) + перлин-шум. Триггеры: попадание (средняя), смерть
  моба (сильная), урон игроку (сильная). На каждый выстрел тряски нет — отдача
  выражается смещением прицела (recoilOffset из снапшота) и вспышкой ствола.
- **Партикли**: встроенный Particle System — вспышка ствола, искры попадания,
  искры `ProjectileBlocked`, взрыв смерти моба.
- **Звук с рандомом питча** (±диапазон в конфиге): выстрел, попадание, смерть
  моба, дэш, урон игроку. Пул `AudioSource`, лимит одновременных голосов на тип
  SFX + минимальный интервал (анти-фазинг/клиппинг при hold-огне).
- **Обратная связь урона игроку** (`PlayerDamaged`): винетка/вспышка экрана +
  тряска + звук.
- **Отклик на вводе** (тик 33 мс не должен ощущаться): прицел и разворот
  аватара — per-frame; вспышку ствола и звук выстрела допустимо играть немедленно
  по вводу (косметика — та же модель, что Э2 разрешает клиенту), авторитетный
  снаряд — от события тика; опция экстраполяции локального аватара на alpha —
  параметр `GameFeelConfig`.
- **Персистентность** (Р2/Р3 — уточнение ADR-001 §10): гильзы, декали, трупы —
  до конца **захода** в пределах FIFO-лимитов (`GameFeelConfig`; дефолты: 1024
  гильз, 512 декалей, 64 трупа — при переполнении переиспользуется старейший;
  визуально неотличимо от «навсегда», кадр жив). Трейсер живёт со снарядом +
  `tracerFadeSeconds` после его смерти («не исчезают» ADR-001 §10 — про следы
  на арене, не следы полёта). Гильзы: PhysX-симуляция `casingPhysicsSeconds`,
  затем сон и слой без взаимных коллизий.
- **Декали**: URP Decal Renderer Feature (добавляется в Renderer-ассеты) +
  кольцевой буфер `DecalProjector`. **Трейсеры**: `TrailRenderer` / Trails-модуль
  Particle System. Свои ленты/квады не пишем.
- Все числа — `GameFeelConfig`/`CameraConfig`, hot-tweak обязателен.

### 3.12. Смерть, рестарт, пауза, метрики

- **Смерть**: `PlayerDied` → мир в состоянии `PlayerDead`: тики продолжаются
  (мобы и снаряды доигрывают фоном под оверлеем), ввод игрока игнорируется,
  урон игроку не применяется, метрики заморожены на тике смерти. Активные
  дэш/i-frames обнуляются в тике смерти; hitstop принудительно завершается до
  показа оверлея; все защёлки ввода сбрасываются; клавиша рестарта активируется
  через ~0.5 с после показа (защита от случайного мгновенного рестарта).
- **Оверлей «Носитель потерян»** (uGUI): подписи по словарю мира (заход/цикл),
  значения: убийства, волны, время, точность (попадания/выстрелы), число дэшей,
  полученный урон, seed (+ пометка `configTweaked`).
- **Рестарт** = полный teardown+rebuild: новый `SimulationWorld(seed, config)`;
  очистка всех персистентных Presentation-объектов и пулов (трейсеры, гильзы,
  декали, трупы, партикли, звуки); сброс аккумулятора, обоих снапшотов, буфера
  событий, защёлок, hitstop, тряски и позиции камеры. Никакого статического
  состояния в Simulation (тест: два мира подряд с одним seed → равные хеши);
  проверка утечек — 5 рестартов подряд возвращают счётчики к базовым.
  Варианты: новый seed (R / кнопка оверлея) и **тот же seed** (Shift+R) —
  воспроизведение захода. Seed генерируется в Presentation
  (`Environment.TickCount64`), логируется; дев-поле принудительного seed.
- **Дев-пауза**: Escape — симуляция не тикает, аккумулятор сбрасывается, меню
  «продолжить/рестарт/выход»; уровень дев-удобства, в Э2 не переносится.
- **Метрики** — состояние Simulation (в хеше, §3.3): kills, wavesCleared,
  shotsFired/shotsHit (точность), dashesUsed, damageTaken, deathTick;
  дублируются в лог — материал плейтест-итераций (13а).

### 3.13. Тесты (TDD, NUnit EditMode — до кода каждой механики)

Группы: аккумулятор (`FixedStepAccumulator`: N тиков в одном кадре ≡ N кадров
по тику; кап 0.25 с; защёлка потребляется ровно одним тиком), конвертация
SO→`SimConfig` (полнота маппинга, валидация, миграция hot-tweak), моментум
(разгон/трение/кап), дэш (длительность/кулдаун/i-frames/буфер/свип), коллизии
(стена изнутри, препятствие, скольжение без ускорения, угол без залипания),
боёвка (кулдаун с переносом остатка, свип-попадание, матрица поражения, отдача),
AI (переходы по дистанции, телеграф, обход препятствия, LoS-гейт огня,
упреждение и вырождения), волны (состав/тайминг от seed, отбраковка,
завершаемость, долг спавна), события (набор, порядок, tick-поле, переполнение),
детерминизм.

Обязательный минимум негативов и вырождений:
1. урон в окне i-frames не меняет HP; тот же урон тиком позже — меняет;
2. снаряд сквозь препятствие в моба за ним → `ProjectileBlocked`, урона нет;
3. свип: попадание при шаге за тик больше диаметра цели;
4. упреждение при неподвижном игроке = точный выстрел; скорость цели ≥ скорости
   снаряда → фолбэк без NaN;
5. волна при полностью занятом кольце: завершается за конечное число операций,
   долг отрабатывается позже;
6. враждебный ввод (NaN/Inf/нулевой/сверхдлинный `moveDir`, `aimPoint` 10^9) —
   состояние конечно, хеш стабилен;
7. переполнение капов мобов/снарядов/событий — детерминированно, без аллокаций;
8. два мира подряд с одним seed → равные хеши (нет статики);
9. save → 500 тиков → restore → 500 тиков → хеши равны прогону без restore;
10. хеш-детерминизм: скриптованный от seed ввод (движение+дэш+hold-огонь+волны
    обоих мобов) × 1000 тиков, два прогона → равные хеши; разные seed → разные;
11. несколько удалений в одном тике не теряют/не дублируют сущности (swap-remove);
12. изменение каждого поля состояния меняет хеш;
13. **ноль аллокаций**: 1000 тиков насыщенного мира — штатный констрейнт
    `Is.Not.AllocatingGCMemory()`;
14. golden-хеш насыщенного сценария — закрепляется в таске финализации (во время
    активных итераций механик не пинится).

Существующие 7 тестов Э0: pinned-тесты сохраняются (адаптация сигнатур — §3.3).
