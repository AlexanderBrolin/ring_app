# Spec: Этап 1 «Боёвка соло, без сети» (app-88s)

**Дата:** 2026-08-02 · **Статус:** на апруве владельца
**Вход:** ADR-001 (§5, §9, §10), ADR-002 (§3, §4, §5, §8 Этап 1), ADR-003 §9,
handoff_app_server.md, brainstorm 2026-08-02
**Ветка:** `feature/app-88s-stage1-solo-combat` (worktree `.worktrees/app-88s-stage1-solo-combat`)

## 1. Цель

Ядро удовольствия: 5 минут соло-геймплея, в которых стрелять приятно. Движение с
моментумом, дэш с i-frames, камера ¾, прицел курсором, одно оружие с физическими
снарядами, два типа мобов на стейт-машинах, волны от seed, HP/смерть/рестарт,
полный game-feel-пасс по чеклисту ADR-001 §10. Вся игровая логика — в `Simulation`
(чистый C#, тики), баланс — в ScriptableObjects, Presentation — отдельным слоем.
Сеть, зоны арены, лут, способности — не в этом этапе.

## 3. Скоуп

### 3.1. Слои и asmdef

- **`Ring.Simulation`** (есть) — вся игровая логика; новые подпространства
  `Movement`, `Combat`, `AI` + расширение `Core`. По-прежнему `noEngineReferences`,
  только `Unity.Mathematics`.
- **`Ring.Data`** (новый asmdef, `Assets/Scripts/Data/`) — ScriptableObject-классы
  баланса + конвертация в plain `SimConfig`. Ссылка на `Ring.Simulation`
  (использует его типы конфигов), UnityEngine разрешён.
- **`Ring.Presentation`** (новый asmdef, `Assets/Scripts/Presentation/`) — раннер
  тика, интерполяция, камера, VFX/звук/game feel, input-обвязка, death screen.
  Ссылки: `Ring.Simulation`, `Ring.Data`, `Unity.InputSystem`, `Unity.Mathematics`.
- Поток данных за кадр: `Input → SimInput → N×Tick() → снапшот+события → рендер/VFX`.

### 3.2. Тик-петля (Presentation)

- `SimulationRunner` (MonoBehaviour): аккумулирует `Time.deltaTime`,
  `while (acc ≥ TickDt) world.Tick(input)`; кап аккумулятора 0.25 с (защита от
  спирали смерти); alpha = `acc / TickDt` — интерполяция рендера между предыдущим
  и текущим снапшотом.
- Кнопочные действия (Dash, край Fire) **защёлкиваются** между тиками: нажатие
  между тиками не теряется, потребляется следующим тиком.

### 3.3. Модель данных и детерминизм (Simulation)

- Структуры: `PlayerState` (pos, vel, aim, hp, dashTimer/cooldown/i-frames,
  fireCooldown), `MobState` (id, type, pos, vel, hp, aiState, stateTimer,
  fireCooldown), `ProjectileState` (id, owner, pos, vel, damage, radius, ttl).
  Все векторы — `float2` (Unity.Mathematics).
- Списки предаллоцированы; удаление — swap-remove (детерминировано: операции
  идентичны при идентичном входе); ID — монотонный счётчик мира.
- `StateHash()` — канонический порядок: tick → rng.state → player → mobs (порядок
  списка) → projectiles (порядок списка) → wave-state. Float — в хеш сырыми битами
  (`asuint`).
- Ограничение (перенос из Э0): детерминизм подтверждается в рамках одного
  билда/машины; кросс-платформенный float — вопрос Этапа 2.

### 3.4. Движение и симуляционная физика

- Моментум: ускорение к желаемому направлению, трение при отпущенном вводе,
  кап максимальной скорости.
- Дэш: фиксированная скорость/длительность, кулдаун, окно i-frames (урон
  игнорируется), ввод буферизуется.
- Коллизии: все сущности — круги; арена — внешняя стена (окружность) +
  препятствия-круги из `ArenaConfig`. Разрешение — выталкивание + скольжение
  вдоль препятствия. Снаряды при контакте со стеной/препятствием умирают
  (событие + декаль на стороне Presentation).
- Разделение мобов (separation): мягкое расталкивание круг-круг, чтобы волна
  не схлопывалась в точку.

### 3.5. Боёвка

- Оружие одно: скорострельность (hold — непрерывный огонь), скорость/урон/радиус/
  время жизни снаряда, разброс, отдача как смещение точки прицела с возвратом
  (ADR-001 §9; считается в Simulation — влияет на направление снарядов, т.е. на
  исход) — всё в `WeaponConfig`.
- Попадание: круг снаряда × круг цели → урон, событие `ProjectileHit`
  (позиция, цель, фатальность), снаряд умирает.
- Смерть моба → событие `MobDied` (позиция, тип) → труп на стороне Presentation
  (персистентен до конца сессии).
- Игрок: HP, урон от контакта ChaserDrone и снарядов GunnerDrone; i-frames дэша
  игнорируют весь урон; смерть → событие `PlayerDied`.

### 3.6. AI и волны

- `ChaserDrone`: `Idle → Chase → Attack` (замах с телеграфом → контактный удар →
  откат); телеграф-тайминги в конфиге — база для game feel уклонения.
- `GunnerDrone`: `Idle → Reposition` (держит предпочтительную дистанцию) → `Fire`
  (стреляет с упреждением по скорости игрока; сила упреждения `leadFactor` 0..1 —
  в конфиге).
- Мобы обсчитываются на полном тикрейте 30 Гц (10–15 Гц из T5 — серверная
  оптимизация Этапа 2, в соло не нужна).
- Волны: `WaveConfig` — пауза между волнами, рост численности, соотношение
  типов по индексу волны; спавн — точки на кольце у внешней стены из RNG мира,
  с отбраковкой позиций внутри препятствий. Всё детерминировано от seed матча.

### 3.7. Контракт Simulation↔Presentation

- **Снапшот**: read-only представление состояния после тика; Presentation хранит
  предыдущий+текущий и интерполирует (позиции, повороты).
- **События тика** (переиспользуемый буфер plain-структур, дренится после пачки
  тиков): `ProjectileFired`, `ProjectileHit`, `ProjectileBlocked` (стена/препятствие),
  `MobSpawned`, `MobDied`, `PlayerDamaged`, `PlayerDashed`, `PlayerDied`,
  `WaveStarted`. Payload — позиция/тип/ID, ничего лишнего.
- UnityEngine внутрь Simulation не протекает; в Э2 те же события лягут на
  репликацию.

### 3.8. Input

- `InputActions`-ассет, map `Gameplay`: `Move` (WASD), `Aim` (позиция мыши),
  `Fire` (ЛКМ, hold), `Dash` (Space). Aim конвертируется лучом камеры в плоскость
  арены → `float2` сим-координат.
- `SimInput` (plain): `moveDir` (нормализован), `aimPoint`, `fireHeld`
  (зажат в момент сэмпла ИЛИ нажимался с прошлого тика — клик короче тика не
  теряется), `dashRequested` (защёлка). Только эта структура пересекает границу
  Simulation.

### 3.9. Баланс: SO → SimConfig

- SO-ассеты в `Assets/Data`: `HeroConfig`, `WeaponConfig`, `MobConfig` (×2 ассета:
  Chaser, Gunner), `WaveConfig`, `ArenaConfig`, `GameFeelConfig`, `CameraConfig`.
- На старте матча `Ring.Data` конвертирует SO в plain-структуру `SimConfig` →
  конструктор мира. Числа game feel/камеры Simulation не касаются — их читает
  Presentation напрямую из SO.
- **Hot-tweak**: правка чисел в инспекторе в PlayMode + горячая клавиша —
  пересборка `SimConfig` и применение к живому миру без перезапуска (состояние
  не сбрасывается).

### 3.10. Грейбокс-арена и сцена

- Истина — `ArenaConfig` (радиус, список препятствий: позиция+радиус); из него
  Simulation берёт коллизии, Presentation строит грейбокс примитивами Unity
  (пол, кольцо стены из сегментов, препятствия-цилиндры). Расхождение сим/визуал
  исключено по построению.
- Стиль минимальный в духе ADR-001 §10: тёмная среда, эмиссивные материалы
  снарядов/подсветок; лоуполи-арт — не в этом этапе.
- Сцена `Main.unity` дополняется: раннер, камера-риг, спавн игрока, overlay
  смерти. Мишени для вехи 2 плейтестов — статичные болванки (те же MobState без AI).

### 3.11. Game-feel-пасс (полный чеклист ADR-001 §10)

- **Hitstop**: замирание Presentation 30–50 мс на подтверждённое попадание;
  скоуп (только цель / весь кадр) — параметр; симуляция не останавливается (6а).
- **Вспышка шейдера** цели (URP emission flash, длительность/цвет в конфиге).
- **Микротряска камеры**: перлин-шум, амплитуда/частота/затухание в конфиге;
  триггеры — выстрел (слабая), попадание (средняя), смерть моба (сильная).
- **Партикли**: вспышка ствола, искры попадания, взрыв смерти моба. Встроенный
  Particle System, без сторонних пакетов.
- **Звук с рандомом питча** (±диапазон в конфиге): выстрел, попадание, смерть
  моба, дэш, урон игроку. Плейсхолдеры — CC0-паки Kenney (wav, через LFS).
- **Персистентность до конца сессии**: трейсеры (trail снаряда), гильзы
  (Presentation-PhysX, не despawn'ятся), декали попаданий, трупы мобов.
- Все числа — в `GameFeelConfig`, hot-tweak обязателен.

### 3.12. Смерть, рестарт, метрики плейтеста

- `PlayerDied` → overlay «Носитель потерян»: убийства, волны, время выживания,
  seed матча (для воспроизводимости) → рестарт по клавише с новым seed.
- Те же метрики пишутся в лог — материал для плейтест-итераций (13а).

### 3.13. Тесты (TDD, NUnit EditMode — до кода каждой механики)

Группы: моментум (разгон/трение/кап), дэш (длительность/кулдаун/i-frames/буфер),
коллизии (стена, препятствие, скольжение, снаряд-стена), боёвка (кулдаун огня,
попадание, урон, смерть, отдача), AI (переходы стейтов по дистанции, телеграф,
упреждение Gunner), волны (состав/тайминг/позиции от seed, отбраковка в
препятствиях), события (набор и порядок за тик), детерминизм (два прогона со
скриптованным от seed вводом × 1000 тиков → равные хеши; разные seed → разные).

### 3.14. Финализация

- Полный EditMode-прогон + сборки ×3 (Linux server, Windows client, Linux client)
  свежими командами; секрет-чек перед коммитами; дерево чистое после сборок.
- DoD-плейтест владельца → итерации до «приятно».
- PR → merge агентом → `bd close` тасков и эпика с evidence; jsonl-дрифт —
  chore-коммитом; handoff — по команде владельца.

## 5. DoD Этапа 1 (ADR-002 §8, дословно + evidence)

- Плейтест владельца: **5 минут соло-геймплея, «стрелять приятно»** — вкус решает
