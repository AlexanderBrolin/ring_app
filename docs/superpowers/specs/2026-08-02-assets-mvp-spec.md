# Спека: ассеты MVP — импорт паков моделей и анимаций (Фаза А)

**Дата:** 2026-08-02 · **Эпик:** app-zuo · **Ветка:** `feature/app-zuo-assets-mvp`
**Вход:** [ASSETS-001](../../adr/ASSETS-001-Модели-и-анимации.md) (спека владельца +
его решения 1–6 в преамбуле), ADR-001 §10, ADR-002 §4 (Critical Rules 8/9), ADR-003 §5/§9.
**Статус:** черновик → на апрув владельца.

## 1. Цель и границы

Проект не содержит ни одной модели (игрок — капсула, мобы — примитивы, арена —
грейбокс). Задача — завезти в репозиторий утверждённые CC0-паки моделей и анимаций
и подготовить их к подключению, **не подключая к геймплею**.

Работа идёт параллельно активной сессии Этапа 1 (ветка
`feature/app-88s-stage1-solo-combat`, фазы 7–9 в работе), поэтому жёсткое правило:
**Фаза А — только аддитивные файлы.** Не трогаем: `Main.unity`, любые файлы
`Scripts/Presentation`, `Scripts/Editor` (существующие), `Assets/Data`, `Prefabs/`
существующие, бутстрап сцены. Конфликтов при мердже Э1 → main быть не может
по построению.

Фаза Б (подключение моделей к `PlayerView`/`MobView`/бутстрапу, маппинг мехов на
Chaser/Gunner, тайминг деша) — **отдельный issue, blocked мерджем Э1**; в этой спеке
только зафиксирован её скоуп (§8).

## 3. Скачивание и раскладка

- Скачиваю я (агент), браузером с itch.io/quaternius.com; страницы паков проверяю
  на явную лицензию CC0 (ASSETS-001 §5).
- Исходные архивы → `$RING_ROOT/assets-src/` (вне git, бэкап владельца).
- В репо — только импортированное:

```
client/Assets/ThirdParty/
├── UniversalAnimationLibrary/   # Models/ Animations/ Materials/ Textures/
├── UniversalAnimationLibrary2/  # Animations/
├── AnimatedMechPack/            # Models/ Materials/ Textures/  (клипы вшиты в FBX)
└── SciFiEssentialsKit/          # Models/ Materials/ Textures/
```

- Внутри паков ничего не переименовываем (ASSETS-001 §4.1); из мульти-форматных
  паков берём только FBX-вариант + текстуры — не тащим OBJ/Blend/glTF-дубли
  (экономия LFS: бинарники и так идут через LFS, правило 8 — `.gitattributes`
  уже покрывает fbx/png/etc.).
- `CREDITS.md` в корне репо: пак → автор → лицензия → URL (CC0 фиксируем всё равно).

## 4. Импорт-настройки (через идемпотентный editor-бутстрап)

Настройки импортеров задаёт новый editor-скрипт
`client/Assets/Scripts/Editor/ThirdPartyImportBootstrap.cs` (`Ring.Editor`, по образцу
`StageOneSceneBootstrap`: идемпотентный, запускается batchmode `-executeMethod`).
Новый файл — аддитивно, существующие editor-скрипты не трогаем.

- **Кукла UAL:** Rig → Humanoid, Avatar = Create From This Model; все клипы UAL/UAL2
  используют этот Avatar (один риг — ретаргет не нужен, но Avatar общий).
- **Роботы (Mech Pack, Sci-Fi Kit):** Rig → Generic, клипы — вшитые в их FBX;
  в Humanoid не конвертируем.
- **Root motion OFF везде** — позицию задаёт симуляция (сервер), анимация — чисто
  визуальный слой (ADR-002 Critical Rule 3).
- **Loop Time:** on для циклических (idle/walk/jog/sprint), off для one-shot
  (death/hit/attack). Списки клипов уточняются по факту скачивания.
- **Материалы:** конвертация в URP (Convert to URP / пересоздание материалов),
  критерий — ни одного розового меша в превью-сцене.

## 5. Animator-контроллеры (заготовки, к геймплею не подключаются)

- `PlayerAnimator.controller`: 2D Freeform Directional blend tree (параметры
  MoveX/MoveY) — Idle/Walk 8-dir/Jog-Sprint; стейты HitReact, Death (2–3 варианта),
  Shoot/Aim через Avatar Mask верхней половины (Gun_*-клипы). Деш: если в UAL/UAL2
  есть подходящий Roll — добавляю стейт-заготовку; нет — стейт не делаю, в Фазе Б
  процедурный визуал (наклон + VFX). Факт фиксирую в bd note.
- По контроллеру на каждого из 4 мехов + на роботов Sci-Fi Kit: стейты из вшитых
  клипов (ожидаем idle/walk/attack/death — проверка по факту, состав перечисляю
  в bd note).

## 6. Превью-сцена (верификация владельцем)

`client/Assets/Scenes/AssetPreview.unity` — собирается новым идемпотентным
бутстрапом `AssetPreviewSceneBootstrap.Apply` (конвенция проекта: сцены — только
бутстрапами). В Build Settings НЕ добавляется. Содержимое: кукла-Сборщик с
`PlayerAnimator`, шеренга мехов и роботов со своими контроллерами (каждый крутит
idle/walk), Директор-заглушка (крупнейший робот, scale ×1.5–2, тёмный материал +
emissive), ящики-лут, простой свет в духе «мрачный неон». Владелец открывает сцену
в Editor (PlayMode) и оценивает.

## 7. Верификация Фазы А (evidence before claims)

1. Свежий baseline: полный EditMode-прогон в этом worktree **до** импорта.
   Ветка форкнута от main (`8718d02`), Э1 ещё не смержен — ожидание: все тесты
   Э0 зелёные (детерминизм); счётчик фиксирую фактом прогона.
2. После импорта: batchmode-импорт и бутстрапы отрабатывают без ошибок в логе;
   полный EditMode-прогон снова зелёный (Simulation не тронута — прогон
   подтверждает целостность проекта).
3. Сборка Linux headless проходит (модели не в билд-сценах — размер билда
   не раздувается; проверка, что импорт ничего не сломал).
4. **Веха-плейтест владельца: превью-сцена** — вкус решает владелец; фидбек → bd note.

## 8. Скоуп Фазы Б (отдельный issue, здесь не делаем)

## 9. Риски

- Состав клипов/моделей внутри паков известен приблизительно до скачивания —
  спека фиксирует правила отбора, а не пофайловый список; расхождения → bd note,
  развилка по скоупу → стоп и вопрос владельцу.
- GitHub LFS-квота (free tier ~1 ГБ storage/bandwidth): смотрю суммарный размер
  импортируемого ПЕРЕД коммитом; если счёт идёт на сотни МБ — стоп и вопрос
  владельцу (усечение паков до используемого).
- Параллельная Э1-сессия активно гоняет Unity batchmode: свои Unity-прогоны
  запускаю только убедившись, что не мешаю (не одновременно с их тестами).
