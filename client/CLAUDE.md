# CLAUDE.md — `client/`: Unity-проект «Кольца», правила клиентского трека

Этот файл — правила для агентов **клиентского трека** (Presentation, UI, арт, звук,
game feel). Server-трек (владелец проекта) работает в этом же Unity-проекте по корневому
`CLAUDE.md` и своему session-handoff'у — правила зон ниже обязательны для всех, ролевые
правила адресованы клиентскому треку.

Обязательное чтение до первой работы: корневой [CLAUDE.md](../CLAUDE.md) репозитория,
[docs/adr/ADR-001-Концепт.md](../docs/adr/ADR-001-Концепт.md) (особенно §4.1 — социальная
динамика/войс/фразы и §9–10: перспектива, боёвка, стиль, game-feel-чеклист),
[docs/adr/ADR-003-Сеттинг.md](../docs/adr/ADR-003-Сеттинг.md) (визуальный язык мира,
Директор, голос хозяина, словарь §9 — термины UI берутся отсюда)
и [docs/adr/ADR-002-Разработка.md](../docs/adr/ADR-002-Разработка.md).

## Зоны (граница — asmdef + CODEOWNERS)

**Клиентскому треку МОЖНО менять:**

- `Assets/Scripts/Presentation/` — рендер, VFX, звук, game feel, камера;
- `Assets/Scripts/Meta/` — UI лобби, REST-клиент меты (UI-часть);
- `Assets/Art/`, `Assets/Audio/`, визуальные префабы и сцены;
- `Tests/` для своего кода (Presentation-тесты приветствуются, где тестируемо).

**НЕЛЬЗЯ (server-ownership; PR в эти пути не пройдёт без апрува владельца — CODEOWNERS):**

- `Assets/Scripts/Simulation/` (включая Core, Movement, Combat, Abilities, AI, Objectives);
- `Assets/Scripts/Networking/`, `Assets/Scripts/Server/`, `docker/`, `../server/`;
- `Assets/Scripts/PresentationNet/` — сетевой бэкенд презентации (сборка
  `Ring.Presentation.Net`): единственная сборка СЛОЯ ПРЕЗЕНТАЦИИ, которой
  открыт FishNet (в клиентский билд компилируются ещё `Ring.Networking`,
  `Ring.Server` и `MetaVoiceChat` — ни одна из них не рисует; `Ring.Editor` и
  `Ring.Simulation.Tests` ограничены платформой Editor). Заведена отдельной
  ровно ради этой границы — `Assets/Scripts/Presentation/` сетевых
  зависимостей не имеет и иметь не должен, поэтому ссылки на FishNet или
  `Ring.Networking` в `Presentation.asmdef` не добавляются: нужен сетевой
  доступ — он живёт здесь;
- `Assets/Data/` (ScriptableObjects баланса) — правки возможны, но ТОЛЬКО отдельным PR
  с ревью владельца, не вперемешку с визуальными изменениями.

Нужно изменение в чужой зоне (новое событие из симуляции для VFX, поле в снапшоте,
хук для UI) — заведи bd-issue с описанием контракта и зависимостью на свою задачу;
реализует server-трек.

## Незыблемые правила (из CRITICAL RULES, корневой CLAUDE.md)

- **Клиент не решает игровые исходы** — урон, хиты, смерть, лут, захваты, ульты,
  эвакуации считает только сервер. Клиент предсказывает ТОЛЬКО собственное движение/дэш;
  всё остальное — интерполяция и косметика. PR, нарушающий это, отклоняется.
- Расхождения предсказания и сервера маскируются VFX, не «подправкой» логики.
- В `Assets/Scripts/Simulation/**` не появляется UnityEngine-зависимостей — если твоя
  фича «просит» этого, значит она спроектирована не в том слое: неси в bd-issue.
- Игровые параметры — в ScriptableObjects (`Assets/Data`), не в коде.
- Сторонние ассеты/пакеты — только с записью в ADR-002 §1 (bd-issue владельцу).

## Game feel (ядро ценности клиентского трека)

Чеклист ADR-001 §10 обязателен на каждое попадание: физически корректная реакция на выстрел, вспышка шейдера цели, микротряска камеры, партикль, звук с рандомизацией питча. Трейсеры, гильзы, декали
и трупы не исчезают до конца матча. Стиль — мрачный неон: тёмная среда + эмиссивные
снаряды/способности; картинку тащат свет и VFX, ассеты — лоуполи.
Все числа game feel — в ScriptableObjects для hot-tweak в PlayMode: вкус владельца
проверяется плейтестом, не автотестом.

## Процесс

1. Задача — только из bd (`bd ready` → `bd update <id> --claim`); трекер общий, в этом
   репо (`.beads/`, префикс `app-`).
2. Ветка на задачу → работа → PR (`gh pr create`) → merge после ревью. Прямых push
   в main нет (branch protection).
3. Перед «готово»: сборка клиента + ручной плейтест; сетевые фичи — с latency simulator
   80 мс RTT + 5% loss (иначе фича не считается готовой).
4. Перед кодом с любым API (Unity, FishNet, DOTween) — свежие доки через Context7.
5. Перед коммитом: `git status --short --untracked-files=all |
   grep -E '\.(env|pem|key)$|secrets/'` — пуст; бинарники — только через Git LFS.
6. Session handoff клиентского трека — [docs/handoffs/client.md](../docs/handoffs/client.md):
   прочитать в начале сессии, обновить в конце (структура — по шаблону в самом файле).
